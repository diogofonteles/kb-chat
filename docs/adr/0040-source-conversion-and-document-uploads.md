# 0040 — From a source to `raw/`: structured conversion with kept originals and provenance (`kb-map convert`), and documents and links sent from the app through a doc-ingest job on the publishing Mac

- Status: proposed (2026-11-16, KBC-148, KBC-149; the decisions are the recommended defaults of [`docs/research/2026-11-16-source-to-raw.md`](../research/2026-11-16-source-to-raw.md), and the owner can change them)
- Amends: [0039](0039-collection-map.md) (kb-map gains `convert` and `reconvert`; a section under "Descrição gerada" is out of the map), [0003](0003-facets-from-frontmatter-catalog.md) (the catalog reads the provenance keys; `raw/_originals/` is never a document), [0035](0035-tracks-as-kb-documents.md) §3 (a Mac marked "Publica no acervo" also takes doc-ingest jobs, under the same vault lock), [0022](0022-media-library-store-queue-and-streaming.md) (a new job kind, `doc-ingest`, kept apart from `jobs` like kb-publish)
- Keeps: Q7 (the API never writes to the vault: it keeps the file and the job, the Mac converts and writes), [0033](0033-resumable-uploads-tus-core-on-the-item.md) (a document's bytes go by the same tus core, hashed in the browser), [0036](0036-access-levels-per-collection.md) §5 (inserting requires a level; a sent document is born at it)
- Drivers: the owner's requests of 2026-11-16 ("Da fonte ao raw/": the derived text for reading, the native format as evidence; sending documents and links from the app with the same treatment as a text)

## Context

Documents reach the vault as plain `.txt` converted outside the app (`_convert/ready/…/<file>.pdf.txt`): headings, chapters, tables and page numbers are lost, the original is not kept, and nothing says which converter made the text. The map (ADR 0039) cuts sections at headings, so a book with none has nothing to cut. People can send only audio from the app.

## Decision

1. **`kb-map convert <topic> <file|url>…` on the Mac, before kb.** Docling for PDF (text or scanned: OCR and table structure, one `<!-- página n -->` marker per page) and images; MarkItDown for Office, EPUB and saved HTML; Firecrawl for links, Jina Reader when Firecrawl fails or has no key; CSV and JSON as they are, with a page describing them; `.txt`/`.md` as they are. Docling and MarkItDown are an optional extra (`uv sync --extra convert`, local and free); tests replace every converter. Firecrawl, Jina and OpenRouter keys come from the environment or the Keychain item the transcriber stores, only ever in a request header.
2. **The original is evidence.** It is stored once, read-only, in `<topic>/raw/_originals/<sha256>.<ext>` (a Markdown original as `.markdown`, so nothing under `raw/` that ends in `.md` is an original). It is never changed or deleted. The sync sends it with the vault.
3. **Provenance in the frontmatter, set line by line.** `original_sha256`, `original_name`, `converter`, `converter_version`, `converted_at`, `source_path` and, for an image, `generated_description: true`. Every other key (kb's, the owner's) stays byte for byte.
4. **kb names, judges and links.** `convert` hands `kb ingest file` a body-only Markdown that opens with `# <autor ou origem> - <título> - <ano>` (kb 0.0.12 titles and names a document from its first line and reads a frontmatter in the file as body), then adds the provenance keys to the file kb wrote. The same original (by hash) or the same link answers with the existing document.
5. **BR-3 of KBC-148: a weak conversion replaces nothing.** Empty, unreadable, or below 80 % of the current text's useful characters (letters and digits) goes to `map/review-queue.json`.
6. **`kb-map reconvert <topic>`** finds each plain-text source's original by its `source_path` (`_convert/ready/<origin>/<path>.txt` → `<path>`, a doubled extension tried both ways) and then by name in `--from` (default `<vault>/_extract`), converts it, applies rule 5, and swaps only the body and the provenance keys. The document's id, kb's keys, the owner's keys and `source_path` stay (BR-2). It is resumable by construction: what the current converter version made is "current" and skipped; a case in review with the same body waits for `--retry`; each document is written atomically; `--limit` and `--max-usd` bound a run; `--dry-run` converts nothing and lists what would change. kb reclassifies the changed bodies on its next `kb classify` (reconvert prints that step; it spends nothing itself but image descriptions).
7. **A model's description is never the author's words (BR-4).** An image gets the OCR under "Texto da imagem (OCR)" and a short description by a cheap vision model (`kb.toml` `[vision] model`, else `google/gemini-2.5-flash-lite`) under "Descrição gerada", with a note. kb-map marks every section under that heading `fora-do-mapa`, so no dossier cites it; the app shows a note on such a document.
8. **"Ver original" (FR-3).** `GET /api/v1/topics/:topic/documents/:id/original` goes through the document's own gate (a reader who may not see the document gets the same 404 as for none). PDF, images and text show in place; anything a browser would run on this origin (HTML, SVG) and anything else downloads; every answer is `nosniff` and sandboxed by CSP. The document's contract carries `original: { name, generatedDescription }` only when the file is there.
9. **Sending from the app (KBC-149).** `POST /api/v1/topics/:topic/documents` takes a file announced (name, bytes, SHA-256, level) or a link. The same permission as audio (`media-upload`, BR-1). The level follows ADR 0036 §5 (required in a collection with levels, at or below the sender's own). A file's bytes go by tus to `/api/v1/document-uploads/:id/upload`; a different file than announced starts over. The uploads live in `document-uploads.json` in the state directory and the files in `document-uploads/` there (no migration of `media.db`). Repeated (BR-3): the catalog's document with the same original hash or `source_path` link, or an upload of it still on its way, answers 200 `duplicate` with its link (none when it is above the person's level).
10. **The doc-ingest job.** Leased only by a paired transcriber marked "Publica no acervo" (no new marking), after media jobs and kb-publish, one at a time, with kb's budget from the media month (as kb-publish). The Mac, under the vault lock: fetches the file, runs `kb-map convert` (step "convertendo"), kb's `classify`, `index`, `link`, `index` ("classificando"), `kb-map sections --doc` when the collection has a map ("entrando no mapa"), then reports `ready` with the document, `duplicate`, or `failed` with a code and the tool's words (shown to masters only). A crash or a lost lease is retried up to three attempts; the Mac's own setup (no kb key) waits without spending one. A document done on the Mac is "no mapa" until the catalog has it (the next sync), then "pronto". Its level is placed in `document-levels.json` (audited) before it arrives, so it is never "Sem nível". The kept file is removed once the job ends.
11. **YouTube goes through the transcriber (KBC-142 BR-5).** The Mac downloads the link's audio with `yt-dlp` and posts it back; it becomes the sender's recording, with their rights as they stand then, and follows the media path (transcription, tracks, kb-publish). The upload shows "transcrevendo" until the recording is live in the collection.

## Consequences

- Sections are born from headings; citations can name a page; every document can be checked against its original.
- `raw/_originals/` grows the vault and the sync by the size of the originals (about 1,200 PDFs in Hermetismo): the VM's data volume must hold them.
- The map step of doc-ingest runs `kb-map sections` only; the incremental tree and dossier update joins it when `kb-map update` (KBC-142) exists.
- An API from before KBC-149 refuses the new job kind (400); the transcriber then stops asking for it. Update the API before the Mac.
- Not measured here: NFR-1 of KBC-148 (the reconversion of Hermetismo in ≤ 8 h) and NFR-1 of KBC-149 (a 100-page PDF ready in ≤ 15 min) need the owner's Mac and the real vault.
